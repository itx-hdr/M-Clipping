# M clipper autonomous editor development plan

Implementation began on 22 November 2026. Saved drafts retain source copies and support caption/title changes, text insertion/removal, moving sections, split and trim with caption-boundary checks, track locks, protection, revision restoration and conflict/retry handling. Clip and whole-video entry points are connected. Revision-bound H.264/AAC rendering runs in the owner-fair heavy queue, with progress, saved output history, in-dashboard playback and private downloads. Text recommendations use the configured AI provider and support saved explanations, apply/dismiss and stale-revision checks. Caption and title corrections become protected. Rendering uses basic static caption styling with the existing fonts and colours. Advanced caption animations, multimodal first-cut planning, multitrack tools, proxy playback and advanced effects remain pending. M0–M3 are partially implemented. Tests cover real rendering, exact frame count, gaps, retained text, source offsets, ownership, retry handling and mocked AI recommendations. The initial Windows console encoding issue is handled by running the suite with Python UTF-8 mode.

Build an **Open editor** workspace inside the dashboard. A user opens a clip or a full video, chooses an editing brief, and presses **Make first cut**. The result is a playable sequence. Selecting anything the AI added reveals its source, timing, settings, and reason. A user can change one word, remove one effect, restore a cutaway, add their own media, or ask for another suggestion. Editing, reopening the project, and exporting must all use the same saved decisions.

**First release test.** Open a 45-second clip, let M clipper cut a pause, frame the gameplay, and add a hook and captions. Restore the pause, fix a name, remove only the hook, and lock the framing. Ask the AI to improve pacing again. Reopen the editor and export. The restored pause and corrected name survive, the hook stays removed, the framing stays locked, and the exported timing matches the preview. Repeat on a 20-minute video with edits in its first, middle, and last chapters.

Selective restoration now supports one item and its linked captions, protects the restored items from further AI text edits, and rejects conflicting placements. Saved projects have a persistent sidebar entry. Dismissed text recommendations remain suppressed for the same item and wording. The current renderer is fixed at 30 fps and supports one source with chronological or manually rearranged picture sections, static text layers, existing framing layouts and source audio. A transcript-based pacing proposal now supports background review and reversible cut assembly. Full audiovisual first-cut planning, additional media tracks and the advanced finishing milestones remain work to do. The latest editor regression coverage includes selective restore, export failure/restart, stale recommendation bypass attempts and real MP4 frame/range checks. AI tests use a fake provider. The in-app browser now verifies individual-cut restoration, preservation of a later caption correction, and persistence after reload on a disposable fixture. Full browser acceptance of the remaining controls is still pending.


The next implemented slice is **First-cut pacing**, available inside saved editor drafts. Enter a brief, choose **Plan pacing cut**, review the source moments and reasons, uncheck unwanted cuts, then **Apply chosen cuts** and **Render saved sequence**. Planning does not mutate the timeline. History restores the entire prior revision. An accepted proposal records which cuts were applied and which were kept.

Implementation details for the next coding agent:

- `studio/editor/firstcut.py` stores an immutable base revision and a coverage ledger in `editor_first_cuts`. Requests use an operation ID, return 202, and enter the existing owner-fair queue. A second active pacing pass for the same owner is rejected. Project/account deletion respects active passes.
- The current capability is conservative transcript pacing, limited to two-hour sequences and 24 five-minute windows. Captions are grouped by parent section, sentence punctuation, gaps and phrase length. Only phrases inside one source section and one review window are eligible. Up to 120 phrases / 20,000 text characters per window go to the configured provider through `brain.editor_pacing_suggestions` and `ask_ai`. Provider fallback may make more than one call per window. No new source transcription or visual analysis is performed by this pass.
- The model chooses existing phrase IDs with reasons. Unknown IDs, protected content, caption crossings, locked-track changes, overlapping cuts and invalid responses are rejected. A pass permits at most 60 cuts and removal of at most 25% of the saved sequence. Windows without removable evidence, oversized transcript windows and failed windows retain their footage. Phrases crossing a window boundary remain untouched. Absence of captions is never treated as evidence of silence.
- Completed window results persist before the next AI call. Partial passes can apply valid proposals or retry unfinished windows. Interrupted in-flight passes require an explicit retry; queued passes recover at startup. Cancelling prevents subsequent windows and discards an in-flight result, although the provider may finish and charge for that request. The worker/recovery design currently assumes one server process.
- `sequence.extract` removes a half-open frame interval, splits picture sections, maps retained source starts, closes the gap and retimes linked captions/text. Stable split IDs make retries deterministic. Protected words and source content cannot be removed; their timeline positions may shift with earlier cuts. Locked tracks cannot move or change. Cuts are applied from last to first in a single revision transaction. The server resolves the saved proposal IDs, rechecks the base revision and records acceptance atomically; a client cannot substitute different AI operations or a newer base revision.
- API: POST/GET `/api/editor/projects/{id}/first-cuts`, GET `/first-cuts/{pass_id}`, POST `/first-cuts/{pass_id}/decision` for cancel/retry/dismiss. Apply through `/commands` with `base_revision`, `op_id`, `first_cut_id`, and `cut_ids`. Successful acceptance labels history **AI pacing cut**.
- Thirty editor regression tests cover deterministic extraction, protected corrections, track locks, request retries, owner isolation, stale/forged acceptance, cancellation, partial retry, restart recovery, selected-cut recording, excessive-removal rejection, beginning/middle/end coverage for a 20-minute fixture, and an actual FFmpeg render with the expected 105 frames after a half-second cut. AI responses are mocked; semantic edit quality with a real provider remains unverified.

Validation for this increment: the full isolated `python tests/run.py` suite passed before and after the backend changes; the final run included 30 editor tests. `node --check web/editor.js` and `git diff --check` also passed. The disposable browser-test server was stopped; execution policy rejected removal of its temporary fixture folder.

This slice does not yet satisfy the complete M3 exit test. It does not detect visual action or silent pauses, generate new framing/music/effects, preview an unapplied cut or create a sibling sequence. Those capabilities and browser acceptance remain required before claiming autonomous full-video editing is complete.


Individual pacing-cut restoration is now implemented in `studio/editor/restoration.py`. Applied proposal cards expose **Restore this cut**. The command payload is `restore_cut: {pass_id, cut_id}` with the normal `base_revision` and `op_id`. The server derives source footage and linked captions from the immutable saved proposal, resolves the current insertion point from stable neighboring picture IDs and source edges, and inserts one protected picture section plus its captions. Later items shift by the restored duration. Current titles spanning the insertion extend; removed titles remain absent. Other accepted cuts remain applied. Restoration creates one history revision.

The document stores `restored_cuts` markers, so undo/redo and full revision restoration keep the restoration state consistent. Adjacent cuts can be restored in either order. A missing/split neighbor, changed source edge, separated neighbors, crossing caption/picture, duplicate restored item or affected track lock causes a conflict without changing the draft. These cases require resolving the conflict or restoring a whole revision through History. Restoration deliberately recovers source picture/audio and linked captions; independently removed text layers are restored separately through History.

## 3. What the user edits

The media bin holds originals, proxies, transcript tracks, stills, audio and LUTs. Source marks belong to the source monitor. Sequence marks belong to the program monitor. The program monitor shows the selected sequence with timecode, safe-area guides and optional scopes. Clicking a visible object selects its timeline item. A layer picker handles overlapping objects. The timeline has video, graphics, caption and audio tracks, adjustable height, thumbnails, waveforms, track targets, locks, solo/mute and zoom-to-selection.

The inspector shows **Timing**, **Picture**, **Sound**, **Text**, **Effects** and **AI changes** as appropriate for the selection. Each effect has enable, reorder, duplicate, reset and remove. Parameters have numeric entry, units, reset and an animation toggle where supported. Show mixed values for multiselection. A changed value affects only that field. Add opens a searchable list of compatible media, effects, transitions, titles and captions.

The AI panel has three actions. **Make first cut** creates a complete draft sequence from the brief. **Suggest changes** returns independently selectable changes against the current revision. **Edit selection** limits the request to selected items or the marked range. Each card shows timecode, before/after, affected tracks, a plain-language reason, and **Preview**, **Apply**, **Adjust** and **Dismiss**. Preview the changed interval with one second of surrounding context. **Restore original** targets one change. **Undo first cut** targets the entire batch. History shows user and AI edits.

For a narrow viewport, stack program monitor, timeline and inspector in that order, with the bin and suggestions in drawers. Give every drag operation a keyboard or numeric equivalent. Space plays, J/K/L shuttle, arrows step one frame, I/O set marks, V selects, C cuts, M adds a marker, and Ctrl/Cmd+Z undoes. Restore focus after dialogs. Ignore shortcuts while typing or composing text. Show saved, saving, offline, conflict, missing media and failed preview states with the recovery action beside the affected object. Preserve the existing palette, colour-only hover and no-shadow design.

## 4. Timeline contract

**Representation.** A project has named sequences sharing a bin. A versioned sequence document owns track order, clip instances, effects, transitions, keyframes, cues, markers, links, protection and output settings. Assets are immutable references, independent of how many times a clip is used. Use stable UUIDs for entities. Use half-open intervals throughout. Use integer sequence frame indices and a reduced rational rate, e.g. `30000/1001`. Audio offsets use integer samples at 48 kHz. Store source PTS as integers plus the asset time base and first displayed PTS. Round for display only. Map each boundary from its absolute position with rational arithmetic to prevent accumulated drift. Sample boundaries use nearest with ties upwards. Sets of adjacent intervals share the same rounded boundary.

Example persisted fragment, shortened for readability. The video starts at sequence frame 90, plays five seconds from the source at 1×, and is linked to a separate audio instance. At frame 240 the next item can begin.

```json
{
  "schema_version": 1,
  "fps": {"num": 30, "den": 1},
  "canvas": {"width": 1920, "height": 1080, "colour": "rec709"},
  "sample_rate": 48000,
  "tracks": [{"id": "v1", "kind": "video", "locked": false}],
  "items": [{
    "id": "shot1", "track_id": "v1", "kind": "media", "asset_id": "camA",
    "stream_index": 0, "at_frame": 90, "frames": 150, "link_group": "pair1",
    "time_map": [{"frame": 0, "pts": 900000}, {"frame": 150, "pts": 1350000}],
    "effects": [], "origin": {"kind": "ai", "change_id": "change7"}
  }]
}
```

Here the source clock is 1/90000. Production IDs are UUIDs. Knots map local sequence boundaries to source PTS. VFR media selects the displayed source frame whose PTS interval contains the mapped time. A constant slope gives constant speed, repeated PTS holds a frame. For a ramp, integrate a piecewise-linear speed envelope into the time map and retain the editable envelope. Round only the final source lookup. Require monotone source position for forward playback. Map dependent audio/captions from the same knots. Freeze adds silence on linked source audio by default. Keep independent music playing.

**Placement.** Exclusive time spans on each picture track except a declared transition. Separate tracks allow overlays. Gaps display black or underlying tracks and play silence on the affected audio track. Resolve draw order bottom to top, then per-item effect order. A transition references both items, cut frame, alignment and duration. Use source handles beyond the visible edges. Reject a requested duration larger than the handles with an exact suggested maximum. Track mattes reference layer IDs and must form an acyclic graph.

**Editing commands.** All gestures end in one atomic batch, with owner, base revision, operation ID and target IDs. Support add/remove/duplicate/reorder tracks and items, split, move, trim, insert, overwrite, lift, extract, ripple, roll, slip, slide, rate stretch, replace asset, link/unlink, set target/lock, set/unset a property, effect, keyframe, mask, cue, marker or transition. Validate track type, finite values, source bounds, one-frame picture minimum, sample bounds, parameter limits, dependencies and locks before commit. Derived split IDs must be stable on retry. Move attached cues, effects and item-relative markers with their parent. A split duplicates effect state at the split boundary and partitions animations/cues without changing appearance or text timing.

| Operation | Deterministic example on a 30 fps track |
|---|---|
| Insert or overwrite | Start with A [0,90), B [90,180). Insert 30 frames at 60. A splits, its tail starts at 90, B at 120, end 210. Overwrite [60,90) instead and B starts at 90, end 180. |
| Lift or extract | Lift [60,90) and a 30-frame gap remains. Extract the same interval and B starts at 60, end 150. Apply ripple to the selected sync group. Reject the whole command if a locked item must move. |
| Ripple or roll | Ripple A’s right edge +10 with handles and B moves +10. Roll the A/B cut +10 and B loses ten head frames, with its end fixed. |
| Slip or slide | Slip A +10 and only its source in/out change. Slide a middle item +10 and keep its source range and duration, extending its predecessor and shortening its successor. |
| Split edit or match cut | Picture switches at frame 90. Start B sound at 78 for a J-cut, or end A sound at 102 for an L-cut. Match cut aligns two user-marked poses and leaves both source marks inspectable. |

Undo/redo and restore create new revisions. For selective restore store the prior property or removed item, stable neighbours, original media interval and dependent IDs. If another user edit overlaps, show a targeted conflict with both values and allow restoring into a duplicate sequence. A property lock protects that property from subsequent AI passes. A track lock applies to manual and automatic timeline commands until explicitly unlocked.

## 5. How the autonomous edit works

| Stage | Inputs and work | Saved result and recovery |
|---|---|---|
| Brief | Choose whole video, short highlight, or selected range. Collect target duration or “keep full story”, aspect, language, pacing, caption style, silence policy, music asset and protected ranges. Default whole-video mode preserves topic order and source aspect. Existing niche shorts inherit their brief. | Save structured settings and the base sequence revision. A changed brief can generate a sibling draft for comparison. |
| Index | Probe streams, capture rotation/time base, index scenes, speech words, pauses, loudness, black frames and representative frames. Use existing job data when the asset fingerprint and analysis version match. | Store evidence IDs with source PTS, confidence and detector version. Missing speech still permits picture edits. Missing originals expose relink. |
| Cover the whole source | Partition long media into five-minute windows with ten-second overlap. Split near sentence or scene boundaries. Deduplicate evidence by asset and source interval. Consolidate window summaries into ordered topics with entry, exit, key statement and visual evidence. | Keep a coverage ledger for every available interval, including quiet sections. Retry failed windows independently. A draft with unanalysed intervals is labelled partial and retains those intervals by default. |
| Make editorial decisions | Build an ordered outline before cutting. For full video, keep demonstrations and necessary pauses, remove repeated starts or dead air where allowed, balance dialogue, add requested captions, and grade related shots consistently. For a short, identify setup, visible action, reaction and payoff. Prefer silence boundaries and preserve qualifying context. | Each decision has stable evidence IDs, affected word/scene range, intended benefit, expected duration delta and a reversible command. Silence-only or visual-only passages require non-speech evidence before the AI proposes removing them. |
| Assemble and finish | Compile the outline into source edits, then linked sound, captions, framing, graphics, mix and finish. Use only registered operations, supported effects and owned assets. Materialize preset parameters and generated tracking paths. | Apply a validated first cut to a new sequence in one visible history group. Save original assembly as its parent. All accepted parts are editable immediately. |
| Inspect | Check coverage, A/V drift, overlaps, clipped words, one-frame flashes, crop bounds, title safe areas, missing media, caption collisions and peaks. Generate review ranges around suspect events. Sample beginning, interior transitions, payoff and ending. | Keep problems attached to target IDs. Offer a targeted repair with before/after. A failed render or unavailable provider leaves the last playable draft accessible. |

**Proposal format.** Use `{id, base_revision, sequence_id, scope, label, reason, evidence_ids, confidence, target_ids, ops, dependencies, preconditions, estimated_delta_frames}`. Validate the entire compound edit in a dry run, including the final rendered duration. Derive a touched-field list, inverse and before/after values on the server. Require allowed enum values, finite numbers, owned references and a bounded number of operations per request. Group dependent proposals, e.g. a lower third and an animation referring to it. Skip or replan a rejected dependency by ID. The model cannot emit code, file paths, renderer expressions, or arbitrary URLs.

**Authority and memory.** Manual changes set a protection record keyed to the semantic target and field, e.g. corrected word ID, named crop, or removed hook slot. A restored source interval creates a keep-range guard. Dismiss stores a signature of target, intent and evidence. Deleting an AI item leaves a tombstone for that intent, so a new item ID cannot resurrect it. Carry guards through splits, moves, and range-local regeneration. Unlock from the inspector or explicitly include the field in a new brief. Test that the AI can still change unrelated fields on the same shot.

**Partial input and cost.** Send only the evidence needed for the current planning window. Use the configured provider/model through the existing AI module, record usage per stage, set per-run call/token budgets in settings and display projected windows before starting. Cache completed windows and validated proposals by evidence, brief, model and prompt versions. Permit one schema-repair attempt. On timeout, cancellation, exhausted budget or invalid output, keep completed analysis and show **Resume**. With no provider configured, open the original assembly and all manual controls. A heuristics-only draft is labelled as such.

**Concrete example.** “Keep the pause before the reveal, lower the music while I speak, and remove the second zoom.” Resolve “second zoom” against ordered visible zoom effects in the marked range. Show the playhead targets. Create a protected source range, a gain envelope on the music track, and a removal command for that single effect. If there are two music tracks and the selected range cannot resolve which one, present both in the suggestion card. The saved mix envelope exposes its gain, attack, release and individual points.

**Reviewed shorts.** Constrain autonomous edits in a brief-bound short to approved clips and chronology. Side-by-side graphics or overlays must preserve the visible gameplay and payoff. The general editor supports manual projects, other languages and long sequences. Keep policy context on the sequence. For a reviewed short, use the actual retained source evidence and English output, then invalidate approval on any changed export bytes. Route eligible renders through the existing source/final review contract in MCP.md, including full-motion and audio inspection, score ≥85, each dimension ≥17/20, no unresolved issues and the matching file hash. Automated QC records only checks it performed. Keep manual editor downloads, reviewed package export and posting as distinct user actions.

### First-cut defaults and recommendation rules

Treat these as editable product defaults. Measure them against pilot footage and version changes to the defaults. The brief takes priority.

| Decision | Whole-video default | User control or exception |
|---|---|---|
| Narrative | Preserve topic order and substantive steps. Identify repeated takes using aligned transcript spans and nearby scene changes. Pick the complete take with intelligible audio. | Show both takes at their source timecodes with **Swap take**. A repeated line used for emphasis stays when its intent is ambiguous. |
| Duration | Without a requested target, keep all substantive material. For a numeric target, compute the feasible range after pinned content, propose removable intervals and show the remaining delta. | If the requested length is shorter than the locked material, return the shortest feasible duration and the ranges responsible. |
| Silence | Consider pauses longer than 1.2 s between speech units. Look at the frames/audio inside them. For an unambiguous dead pause, retain 250 ms on each side and snap to complete words. | Preserve demonstration time, laughs, music beats, suspense and marked keep ranges. Let the user set the threshold or restore original duration. |
| Framing | Preserve source framing on landscape material unless the aspect changes or a subject is clearly cropped. For a vertical reaction layout, generate named gameplay and face regions and mark uncertain tracks. | Inspector offers fit, fill, manual rectangles and tracking keyframes. Show the source with the proposed crop and safe areas together. |
| Text | Use the chosen display language, up to two caption lines, measured to fit the safe width. Lead with a factual hook only when requested by the brief or short format. | Edit speaker names, casing, punctuation, font, colour, position, emphasis, cue breaks and individual timings. Disable either the hook layer or captions independently. |
| Sound and filler | Normalize final programme loudness to the chosen profile. When music is supplied, propose a dialogue envelope with an initial 9 dB reduction, 80 ms attack and 350 ms release. Leave the music track empty when there is no suitable bin asset. | Expose target loudness, gain points, attack, release and track selection. Filler-word removals are suggested only when the resulting words, breathing and picture cut are intelligible. |
| B-roll, transitions and colour | Choose only bin media with evidence of relevance, prefer straight cuts for dialogue, and apply a consistent correction to shots from the same setup. | Display the proposed cutaway and its source credit. Users can swap the asset, drag either edge, remove the cutaway to reveal the base shot, or bypass the group grade for one shot. |

**Migration example.** A saved piece covers original seconds [600,645). The legacy montage keeps [606,610) then [618,622). On a 30 fps sequence the two linked pairs start at 0 and 120 and end at 240. The piece-local source ranges are [6,10) and [18,22). A word at original second 619 starts at sequence second 5. Store original provenance once and subtract the offset only when resolving the piece PTS. Recover the hook as a graphic, words as linked cues, and the two normalized crop rectangles as separate transformed uses of the same source. Use corrected words for the same source span when available. A source with only the burned-in final file cannot recover the original hidden pixels or captions as separate layers.

## 6. Storage, API and background work

Use additive SQLAlchemy Core tables in `studio/db.py` on SQLite and PostgreSQL. Keep original media and derivatives in owner-scoped storage. Store paths as server-generated relative keys. Place new services under `studio/editor/` as the corresponding milestone needs them. Use `model.py` for schema/validation, `commands.py` for deterministic state changes, `store.py` for transactions, `assets.py` for ingest, `planner.py` for orchestration, `compile.py` for composition, and `routes.py` for the authenticated router. Keep AI service calls in `studio/ai.py` and prompts in `studio/brain.py`.

| Record | Required fields and invariants |
|---|---|
| projects and assets | Project ID, owner, name, created/updated, optional origin job/clip/version. Asset ID, project, role, original filename, relative storage key, byte length, SHA-256, streams, source clock, available intervals and credit. Each import validates content and ownership. Link to a retained owner asset or make a project-owned copy before allowing the origin job to be deleted. |
| sequences and revisions | Sequence ID, project, head revision, name. Revisions keyed by (sequence, revision), with parent, author kind, batch ID, normalized changes, inverse, guard changes and timestamp. Snapshot the initial revision and every 25 changes. Persist the materialized head in the same transaction. Use a versioned schema with explicit migrations and fixture snapshots. |
| requests and suggestions | Unique (owner, resource, operation ID), request digest, committed response. Suggestions store base revision, evidence, dependencies, status and reason. A duplicate request returns the original result. Reuse of an ID with different content returns a conflict. |
| analyses and tasks | Asset hash, analyser version, parameters, range, results key. Task ID, owner, project, immutable revision, kind, status, progress, cancel flag, attempt, lease owner and expiry, output key, error code. Index pending/leased work by status and time. |
| outputs and reviews | Revision, render profile, input fingerprint set, engine version, output digest, original-size path, proxy/preview kind, media check and review IDs. A mutable current-output pointer can reference only a complete verified artifact. Keep prior exports downloadable by version. |

**Write transaction.** Authenticate → load scoped resource → look up operation ID → compare head to base → validate/apply all commands to an isolated copy → insert history/idempotency rows and update head with a conditional update → commit → bump sync. A lost compare-and-swap rolls the whole transaction back. Return 409 with the current revision and touched IDs. The client may replay a disjoint edit once after checking preconditions. Show competing values for overlaps. Autosave groups pointer motion into one gesture, debounces text edits by 400 ms and flushes on blur. Keep unsent batches in owner/project-scoped IndexedDB, clear on sign-out, retry with original IDs after reconnect.

**Proposed routes.** All routes below share `/api/editor`. Use JSON unless a media stream, archive or upload part is explicitly requested. IDs in responses are opaque. Include `schema_version` and `revision` in sequence responses.

| Method and path | Request and result |
|---|---|
| GET /projects · POST /projects | Paginated project list. Create with name, origin (blank, job, or job+clip), and operation ID. Return 201 with project, sequence and initial revision. |
| GET, PATCH, DELETE /projects/{p} | Project/bin summary, rename, or delete. Deletion cancels tasks and releases scoped references. Support deletion retry. |
| POST /projects/{p}/assets/uploads · PUT .../{u}/parts/{n} · POST .../{u}/finish | Reuse chunk-writing, quota and probe logic from existing upload flows. Finish creates a bin asset and analysis task. An editor upload must not start a clipping job. Support duplicate finish and interrupted transfer. |
| GET /projects/{p}/assets/{a}/media · POST .../{a}/relink | Stream source or proxy with authenticated byte-range support. Relink verifies stream and fingerprint. Changed bytes create a replacement asset and require explicit use in the sequence. |
| POST /projects/{p}/sequences · GET /sequences/{s} | Create, duplicate or fork a sequence. Fetch head or named revision, plus paged timeline spans for a long project. |
| POST /sequences/{s}/commands | `{base_revision, op_id, ops}` returns revision, changed IDs, invalidated ranges, undo group and normalized values. 422 includes offending command index, field and recovery hint. |
| GET /sequences/{s}/history · POST /sequences/{s}/history/actions | List grouped edits, then undo, redo or selectively restore with target change ID, base revision and operation ID. |
| POST /sequences/{s}/ai-runs · GET /ai-runs/{r}/suggestions · POST /suggestions/{k}/decision | Start a first cut or scoped suggestion task with brief, selection and base. Preview, amend, apply or dismiss through the same validator. Return 202 for long work. |
| POST /sequences/{s}/previews · POST /sequences/{s}/exports · GET /tasks/{t} · POST /tasks/{t}/cancel | Pin range, revision and profile at submit. Return task ID, status and progress. On completion return an authenticated result link with checksum. |
| POST /projects/{p}/packages · POST /projects/import · GET /outputs/{o}/media | Collect selected sequences and used assets, import a package as a new project, and stream/download completed outputs. A missing file appears in the relink list. |

Example manual change. A successful response returns revision 19 and the invalidated caption interval. A second submission with the same operation ID returns that exact result even after the head advances.

```json
{
  "base_revision": 18,
  "op_id": "4db0c94d-152a-4206-801a-df88b465d7a1",
  "ops": [{"type": "caption.set_text", "cue_id": "cue12", "text": "Wait for the landing."}]
}
```

**Jobs and files.** Lease tasks transactionally. Persist queued → running → succeeded/failed/cancelled with monotonic progress per attempt. Recover expired leases after restart. A cancelled or superseded attempt loses publication rights. Use a disposable short working directory, validate outputs, copy to a staging file on the destination volume, then atomically replace and commit the output pointer. Retry orphan cleanup at startup. An export finishing after a new edit belongs to its requested revision. Limit quick previews per owner and coalesce old ones. Schedule long analysis, proxy and export work on the fair, load-aware path. Make per-chunk deadlines progress-aware. A single short-render timeout cannot govern an hour-long export.

**Lifecycle.** Enforce the existing host/origin/request gate, session scope, upload/drive limits and selected storage root throughout. Return 404 for another owner’s ID, 409 for stale edits, 422 for invalid media or operations, 429 for queue pressure and 507 for insufficient space. Resolve IDs to server-owned files. Validate archive entries, declared/expanded sizes and duplicate names before import. Remove staged bytes on failure. Cancel workers before deleting a project or account and release unreferenced originals only after history, export and other project references are accounted for. Public sharing remains an explicit downstream action.

| Picture | Normalize display rotation, sample aspect and source colour metadata. | Motion and masks | Item keyframes use item-local frames. Store hold, linear and cubic Bézier interpolation with ordered time handles. Persist the generated path/matte as an editable mask asset. | A tracked blur stops when confidence drops, accepts a corrected anchor, then continues. Re-import keeps the selected audio stream and A/V offset within one frame. |
| Audio | Work at 48 kHz internally. Order source/channel map → time stretch → clip effects and envelopes → track bus → dialogue sidechain on music → master gain/limiter. Provide true-peak and integrated loudness readouts and sample-level offset. Missing audio produces silence of the correct length. Store ducking and remix cuts as editable envelopes and media instances. | Two simultaneous clips sum without automatic per-input attenuation. A ducked bed recovers after the line. Muting only the game leaves the mic. Compensate filter delay at section joins. |
| Captions and graphics | Keep raw ASR, corrected words, translated/transliterated variants and cue instances separate. Each cue links to source word IDs or is marked manual. Cutting out a word removes it from playback and SRT. A freeze or reverse defaults to silence/no automatic speech captions over that interval, while the user can add a manual cue. |
| Colour | Start with an SDR Rec.709 working/output profile. Convert range/transfer/matrix on input, expose SDR conversion for HDR footage, tag output accurately, and show the conversion in properties. Bake only pointwise, spatially uniform stages. | Grey balance and legal range survive encode, a selective skin adjustment leaves the background stable, and a LUT with identity values is neutral within quantization tolerance. Mark spatial or temporal effects ineligible for LUT export. |
| Auto-reframe and multicam | Smooth subject trajectories per shot, reset at cuts, respect protected regions, and add user correction anchors. Switching an angle writes picture edits at playhead frames with a continuous chosen audio master. | A 16:9 to 9:16 duplicate preserves the original and its existing motion. Switching three cameras during a sentence creates no duplicated samples, gaps or change of voice. |

**Interactive preview.** Build low-resolution time-aligned proxies (default 540p long-side target for portrait or landscape, aspect preserved), paged thumbnail strips and multiresolution waveform peaks. Virtualize timeline items by visible time and tracks. Use browser playback for plain cuts and immediate transform guides while dragging. Label an approximate overlay preview and request a server-rendered exact range on release. Cache exact previews by revision, source hashes, range, renderer, fonts and settings. Serve a single play-ready segment or a sequence playlist with contiguous presentation times. For a compare action, sync before/after to a source anchor when a cut changes duration. Offer exact preview for any supported operation.

**Long-form export.** Render deterministic bounded chunks at edit or fixed-duration boundaries, with overlap for transitions, interpolation, audio lookahead and effect tails. Derive each chunk from absolute timeline time, discard preroll/postroll once, and stitch on shared frame/sample boundaries. Use identical intermediate format and time base, encode final audio once to prevent AAC delay at each join. Compute whole-program loudness in a separate measurement pass when normalization is enabled. Resume from verified intermediates keyed to inputs and settings. A short sequence can use one chunk. Compare a chunked render to a single-pass reference containing an edit, dissolve and ducking across a chunk boundary.

**Delivery profiles.** Default short export is 1080×1920 at 30 fps, H.264/AAC, matching the current clip workflow. Manifest records fonts, profile, source hashes, engine version and SHA-256. Pin exports for posting by artifact ID so a new draft cannot replace queued media.

**Project transfer.** A ZIP has a schema-versioned manifest, sequences, dependencies, cue/analysis sidecars and an assets directory of named content hashes.
